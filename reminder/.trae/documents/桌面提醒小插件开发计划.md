# 桌面提醒小插件开发计划

## 一、摘要

基于黑马程序员AI大模型就业班的学习场景（课程表、班级班规、学习方法），开发一款Windows桌面提醒小插件。该插件面向IT培训学员，核心解决"学习纪律监督"和"课程进度跟踪"两大痛点。通过市场调研发现，现有提醒工具普遍存在功能臃肿、提醒方式单一、缺乏学习场景定制化等问题。本方案将规避这些缺陷，打造一款轻量、专注、高度定制化的学习提醒工具。

## 三、市场调研结论（竞品分析）

### 3.1 竞品范围
调研了6款主流桌面提醒/日程管理/习惯养成工具：Microsoft To Do、滴答清单桌面版、番茄ToDo、Forest专注森林、Streaks、Habitica。

### 3.2 核心问题与缺陷总结

| 维度 | 主要问题 | 具体表现 |
|------|---------|---------|
| **功能配置** | 提醒方式僵化 | Microsoft To Do重复提醒存在已知Bug（运行1-2天后失效）；多数工具仅支持弹窗/声音，缺乏渐进式提醒策略 |
| | 场景适配差 | 现有工具均为通用型，无IT培训/学习场景专用模板 |
| | 数据同步复杂 | 滴答清单功能丰富但配置复杂，学习成本高 |
| **UI设计** | 界面臃肿 | 滴答清单、Microsoft To Do功能过多，对仅需提醒的用户造成视觉干扰 |
| | 自定义不足 | 番茄ToDo桌面版功能大幅弱于移动端；暗黑模式支持参差不齐 |
| | 操作路径长 | 创建一条提醒平均需3-5次点击，不符合"快速记录"的学习原则 |
| **用户体验** | 打扰程度难控 | 提醒要么太弱（被忽略），要么太强（打断心流），缺乏智能分级 |
| | 学习成本高 | 滴答清单被用户反馈"功能多但上手难"；Habitica游戏化对部分人反而是负担 |
| | 性能占用 | Electron框架应用（如部分桌面版）内存占用高 |
| **创新不足** | 缺乏学习闭环 | 无工具将"提醒-执行-复盘"形成闭环 |
| | 无同伴监督 | 班级学习场景中，缺乏同伴进度可见性和互相监督机制 |
| | 无课程表联动 | 无工具支持与课程表自动同步，需手动维护 |

### 3.3 市场定位空白
- **现有工具**：面向泛用户群体，功能大而全，缺乏垂直场景深度
- **空白机会**：IT培训学员这一垂直群体，需要"纪律监督+课程跟踪+习惯养成"三位一体的轻量工具

## 四、产品定位与差异化策略

### 4.1 目标用户
黑马程序员AI大模型就业班学员，特征：
- 学习强度高（每日课程+晚自习）
- 需要外部纪律约束（班规要求严格）
- 课程进度紧凑（2周密集培训）
- 技术背景（对工具接受度高，偏好简洁高效）

### 4.2 核心定位
**"AI大模型就业班专属学习纪律官"** — 轻量、专注、零干扰的Windows桌面提醒插件

### 4.3 差异化策略（三层）

| 层级 | 策略 | 具体措施 |
|------|------|---------|
| **补齐** | 基础提醒功能 | 课程提醒、作息提醒、习惯打卡，确保不弱于通用工具 |
| **差异化** | 学习场景深度定制 | 课程表自动导入、班规提醒模板、学习阶段自适应、同伴进度看板 |
| **创新** | 智能学习闭环 | 提醒→执行→打卡→复盘→积分排名，形成完整学习反馈循环 |

## 五、功能需求

### 5.1 功能总览

| # | 模块 | 功能描述 |
|---|------|---------|
| 1 | 课程提醒 | 根据导入的课程表，在上课前N分钟弹出提醒，显示课程名称、教室/线上链接、预备内容 |
| 2 | 作息提醒 | 针对班规中的关键时间点（起床、晚自习开始/结束、作业截止）进行提醒 |
| 3 | 习惯打卡 | 将6条班规转化为每日打卡项，支持一键打卡和连续天数统计 |
| 4 | 课程表视图 | 以日历/列表形式展示课程安排，高亮今日课程，区分上课/自习/休息 |
| 5 | 学习统计 | 统计本周出勤率、打卡完成率、专注时长，生成周学习报告 |
| 6 | 同伴看板 | 可选开启，显示班级同学的学习打卡排名（匿名或实名），形成良性竞争 |
| 7 | 智能复盘 | 每日晚自习结束后，弹出当日学习复盘窗口，引导记录3个收获+1个疑问 |
| 8 | 设置中心 | 提醒提前时间、提醒方式（弹窗/声音/托盘闪烁）、开机自启、主题切换 |

### 5.2 核心页面原型设计

#### 页面1：主面板（悬浮窗/桌面小部件）
- **布局**：紧凑卡片式，默认显示"下一个提醒"倒计时
- **元素**：
  - 顶部：当前日期 + 今日课程进度（如"2/4节课已完成"）
  - 中部：下一个事件名称 + 倒计时（如"大模型开发入门V6.0 还有15分钟"）
  - 底部：快捷按钮（打卡、课程表、复盘、设置）
- **交互**：支持拖拽定位、贴边自动收缩为细条、双击展开

#### 页面2：提醒弹窗
- **布局**：屏幕右下角滑入，不抢占焦点
- **元素**：
  - 事件类型图标（课程/作息/习惯）
  - 事件标题 + 时间
  - 快捷操作（我知道了/延迟5分钟/查看详情）
  - 进度条显示今日整体完成度
- **策略**：首次提醒温和（托盘闪烁），若未响应则升级（弹窗+声音）

#### 页面3：课程表视图
- **布局**：周视图为主，支持日/周切换
- **元素**：
  - 时间轴纵向排列
  - 课程块以色块区分类型（理论课/项目课/自习/休息）
  - 点击课程块展开详情（内容大纲、预习链接）
  - 今日高亮显示

#### 页面4：习惯打卡面板
- **布局**：清单式，6项班规对应6个打卡项
- **元素**：
  - 每项：图标 + 班规文字 + 今日状态（未打卡/已打卡）
  - 连续打卡天数徽章
  - 一键全部打卡（谨慎使用，需二次确认）

#### 页面5：每日复盘弹窗
- **触发**：晚自习结束时间到达时弹出
- **布局**：模态对话框
- **元素**：
  - 今日课程回顾（自动列出今日所学模块）
  - 输入框1：今日3个收获（必填至少1项）
  - 输入框2：遗留疑问（可选）
  - 明日预习提醒（自动根据课程表生成）
  - 提交后生成学习日志

### 5.3 状态与边界

| 状态 | 处理逻辑 |
|------|---------|
| 电脑休眠/锁屏 | 唤醒后检查错过的提醒，以摘要形式一次性展示 |
| 用户正在全屏（游戏/视频） | 提醒降级为托盘闪烁，不弹窗打扰 |
| 重复提醒未响应 | 最多提醒3次，间隔5分钟，之后标记为"已错过" |
| 课程表变更 | 支持手动编辑，变更后下次启动生效 |
| 无网络 | 本地运行不受影响，同伴看板显示"离线模式" |

## 六、技术方案

### 6.1 技术选型
- **框架**：Python + PyQt6 / PySide6（轻量、原生Windows体验、低内存占用）
- **数据存储**：SQLite本地数据库（无需服务器，保护隐私）
- **提醒引擎**：Python threading + Windows原生通知API（WinToast）
- **打包**：PyInstaller生成单文件可执行程序
- **课程表导入**：支持从图片OCR识别或手动输入

### 6.2 架构设计
```
桌面提醒插件
├── 主程序（PyQt6）
│   ├── 悬浮窗主面板
│   ├── 系统托盘图标
│   └── 设置对话框
├── 提醒引擎
│   ├── 定时器调度器
│   ├── 提醒策略器（渐进式升级）
│   └── 弹窗管理器
├── 数据层（SQLite）
│   ├── 课程表数据
│   ├── 打卡记录
│   ├── 学习日志
│   └── 用户设置
├── 课程表解析器
│   ├── 手动输入界面
│   └── OCR导入（可选扩展）
└── 同伴同步模块（可选）
    └── 局域网P2P同步（无中心服务器）
```

### 6.3 文件结构

| 文件/目录 | 说明 |
|----------|------|
| `main.py` | 程序入口 |
| `ui/` | 界面模块（主面板、弹窗、设置等） |
| `core/` | 核心逻辑（提醒引擎、打卡逻辑、统计） |
| `data/` | SQLite数据库文件 |
| `assets/` | 图标、音效、样式表 |
| `config.json` | 用户配置文件 |

| `build/` | 打包输出目录 |

## 七、UI设计原则

### 7.1 设计目标
- **轻量**：安装包<20MB，内存占用<50MB
- **无干扰**：默认贴边收缩，仅在需要时展开
- **清晰**：信息层级分明，3秒内获取核心信息
- **专注**：无社交、无广告、无多余功能

### 7.2 视觉风格
- **配色**：以黑马程序员品牌蓝（#0066CC）为主色，搭配中性灰背景
- **字体**：系统默认字体，确保清晰可读
- **动画**：仅使用淡入淡出，避免花哨动效分散注意力
- **主题**：支持浅色/深色模式切换

### 7.3 交互原则
- **一键操作**：核心功能（打卡、确认提醒）均可在1次点击内完成
- **智能默认**：首次启动自动加载示例课程表，用户只需微调
- **渐进披露**：高级功能（同伴看板、复盘分析）默认折叠，按需展开

## 十、假设与决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 技术框架 | Python + PyQt6 | 开发效率高、跨平台潜力、内存占用低于Electron |
| 数据存储 | SQLite本地 | 保护隐私、无需网络、零部署成本 |
| 课程表导入 | 手动输入为主 | 图片OCR作为后续扩展，首期确保准确性 |
| 同伴看板 | 可选功能，默认关闭 | 避免社交压力，尊重个人偏好 |
| 复盘功能 | 每日一次，固定时间触发 | 培养固定习惯，不增加用户决策负担 |
| 打包方式 | PyInstaller单文件exe | 便于分发，用户无需安装Python环境 |

## 十一、风险评估

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| PyQt6在部分Windows版本兼容性差 | 中 | 高 | 测试Win10/Win11，必要时降级到PyQt5 |
| 提醒被Windows通知中心拦截 | 高 | 中 | 同时支持应用内弹窗和系统通知双通道 |
| 用户反馈功能不足 | 中 | 中 | MVP聚焦核心功能，预留扩展接口 |
| 课程表变更频繁 | 低 | 中 | 提供快速编辑入口，支持批量修改 |
