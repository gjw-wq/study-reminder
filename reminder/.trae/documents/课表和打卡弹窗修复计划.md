# 课表日期/课程对不上 + 打卡/课表无数据弹窗修复计划

## 一、问题诊断

### 问题1：课表日期和课程对不上
从截图可以看到：
- 今日是 2026-06-15（星期一）
- 复盘弹窗显示"今日所学课程: 大模型开发入门V6.0"
- 但课表图片显示 6/15 是**休息**日

**根因分析**：
1. `course_data.py` 中 6/15 确实标记为 `is_rest=1`，但 `review_dialog.py` 的过滤逻辑只检查了 `c[4] not in ('rest', 'self_study')`，没有同时检查 `is_rest` 字段（`c[7]`）
2. 更深层问题：`course_data.py` 中的 `COURSE_SCHEDULE` 数据虽然 `is_rest=1`，但 `course_type` 是 `'rest'`。`review_dialog.py` 的过滤 `c[4] not in ('rest', 'self_study')` 理论上应该能过滤掉。但实际运行结果显示"大模型开发入门V6.0"，说明数据库中 6/15 的数据不是休息，而是上课数据。

**真正根因**：`init_course_data()` 使用 `INSERT OR REPLACE`，但数据库中已存在旧数据（之前错误的数据），新数据没有覆盖。因为 `insert_course` 的 REPLACE 需要主键冲突，但主键是自增的，不会冲突，所以旧数据保留，新数据追加。导致 6/15 同时存在"休息"和"大模型开发入门V6.0"两条记录。

### 问题2：打卡和课表点击无数据弹窗
**根因**：`HabitPanel` 和 `CourseView` 继承自 `SubWindowBase`（自定义 QWidget，带 `FramelessWindowHint`），而 `ReviewDialog` 和 `SettingsDialog` 继承自标准 `QDialog`（有系统标题栏、关闭按钮、模态阻塞）。

用户希望打卡和课表也使用 `QDialog` 的弹窗效果（有系统标题栏、关闭按钮、模态显示），而不是当前的自定义无边框窗口。

## 二、修复方案

### 修复1：清除旧数据库，确保数据正确
**文件**：`main.py`

在 `init_course_data(db)` 之前，先清空 `courses` 表，确保旧数据不干扰：

```python
# 清空旧课程数据，确保新数据正确导入
conn = db.get_connection()
cursor = conn.cursor()
cursor.execute('DELETE FROM courses')
conn.commit()
conn.close()
```

### 修复2：将 HabitPanel 和 CourseView 改为 QDialog 弹窗
**文件**：`ui/habit_panel.py`、`ui/course_view.py`

将 `SubWindowBase` 的自定义无边框窗口改为标准 `QDialog`：
- 移除 `FramelessWindowHint` 和 `WA_TranslucentBackground`
- 使用 `setWindowTitle()` 设置标题
- 保留关闭按钮和滚动区域
- `main_panel.py` 中调用 `exec()` 而非 `show()`

### 修复3：修正 review_dialog.py 的课程过滤逻辑
**文件**：`ui/review_dialog.py`

确保同时检查 `course_type` 和 `is_rest`/`is_self_study` 字段：

```python
study_courses = [c for c in courses if c[4] not in ('rest', 'self_study') and not c[7] and not c[9]]
```

## 三、修改文件清单

| 文件 | 修改内容 |
|------|---------|
| `main.py` | 初始化课程数据前清空 courses 表 |
| `ui/habit_panel.py` | HabitPanel 改为继承 QDialog，使用标准弹窗 |
| `ui/course_view.py` | CourseView 改为继承 QDialog，使用标准弹窗 |
| `ui/main_panel.py` | 调用 habit_panel 和 course_view 时使用 exec() |
| `ui/review_dialog.py` | 修正课程过滤逻辑，双重检查 rest/self_study |
